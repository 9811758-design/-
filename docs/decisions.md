# 제품 및 기술 결정

## 확정 결정

### 날짜별 총매출을 포함한 단순 장부

- 상태: 확정
- 결정: 활성 거래 유형은 revenue, purchase와 expense다. 같은 영업일 revenue는 한 건이며 재입력은 수정한다.
- 근거: 메뉴별 POS 없이도 월간 매출과 매출 대비 재료 구매비율을 확인할 수 있다.
- 영향: 메뉴 관리·메뉴별 판매는 제거 상태를 유지하고 월간 캘린더와 총매출 집계를 제공한다.

### 레거시 판매·메뉴 데이터 보존

- 상태: 확정
- 결정: 기존 IndexedDB 데이터와 스키마를 자동 삭제하지 않는다.
- 근거: 업데이트 과정의 데이터 손실과 데이터베이스 개방 실패를 방지한다.
- 영향: 호환용 타입·테이블·migration은 남지만 활성 UI와 집계에서는 제외한다.

### Google Sheets 하위 호환

- 상태: 확정
- 결정: 기존 Spreadsheet 탭·헤더와 행을 보존하고 신규 원격 쓰기는 revenue, purchase와 expense로 제한한다.
- 근거: 이미 연결한 사용자의 백업 파일을 파괴하지 않으면서 제품 범위를 줄인다.
- 영향: revenue는 기존 Transactions 행 규약을 사용하고 호환용 Menus 등 기존 탭 계약은 유지한다. 레거시 sale/menu 큐는 원격 쓰기 없이 종료한다.

### 비율 명칭

- 상태: 확정
- 결정: 재료 구매비 ÷ 총매출은 ‘매출 대비 재료 구매비율’로 표시한다.
- 근거: 재고 사용량을 반영하지 않으므로 실제 원가율이라고 부르면 오해를 만든다.

### 오프라인 우선

- 상태: 확정
- 결정: IndexedDB 저장을 먼저 완료하고 Google 동기화를 후속 작업으로 처리한다.
- 근거: 네트워크 또는 인증 실패가 운영 기록 손실로 이어지지 않아야 한다.

### 시간과 금액

- 상태: 확정
- 결정: 금액은 원 단위 정수, 기간 집계는 Asia/Seoul 기준을 사용한다.
- 근거: 부동소수점 오차와 자정 경계 오류를 피한다.

## 보류 결정

- 기존 판매·메뉴 데이터를 사용자가 직접 내보내거나 영구 삭제하는 관리 기능은 현재 범위 밖이다.
