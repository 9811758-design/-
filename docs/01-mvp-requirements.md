# MVP 요구사항

## 1. 기록

- 사용자는 재료 구매와 운영비 중 하나를 선택해 기록할 수 있어야 한다.
- 재료 구매는 품목명, 수량, 단위, 단가, 날짜와 선택 메모를 입력한다.
- 운영비는 카테고리, 금액, 날짜와 선택 메모를 입력한다.
- 금액은 원 단위 정수로 저장하고 잘못된 입력은 한국어로 안내한다.
- 저장은 IndexedDB에서 먼저 성공해야 하며 네트워크 상태와 무관해야 한다.
- 신규 판매 거래는 도메인 입력 경계와 UI 모두에서 생성할 수 없어야 한다.

## 2. 내역

- 기본 목록과 필터에는 재료 구매와 운영비만 표시한다.
- 기간 및 거래 유형으로 필터링할 수 있어야 한다.
- 두 거래 유형은 수정과 soft delete가 가능해야 한다.
- 앱 재실행 후에도 로컬 데이터가 유지되어야 한다.

## 3. 대시보드

- 오늘 총지출을 표시한다.
- 이번 달 총지출, 재료 구매비, 운영비, 거래 건수를 표시한다.
- 빠른 작업은 재료 구매와 운영비 기록으로 연결한다.
- 판매·매출·이익·재료비율 지표를 표시하지 않는다.

## 4. 통계

- 선택 기간의 총지출과 거래 건수를 표시한다.
- 재료 구매비와 운영비를 구분한다.
- 운영비 카테고리별 금액과 비중을 표시한다.
- 기간별 지출 추이를 표시한다.
- 거래가 없거나 총액이 0원이어도 오류나 잘못된 비율을 만들지 않는다.

## 5. 동기화

- 신규 원격 쓰기는 재료 구매와 운영비에만 수행한다.
- 추가·수정·soft delete를 UUID와 버전으로 중복 없이 반영한다.
- 실패한 작업은 큐에 남기고 재시도할 수 있어야 한다.
- 동기화 실패나 권한 거부가 로컬 데이터를 삭제하거나 롤백해서는 안 된다.
- 기존 Spreadsheet의 탭과 헤더 구조 및 과거 행을 자동으로 삭제하거나 덮어쓰지 않는다.

## 6. 호환성과 접근성

- 기존 IndexedDB의 판매·메뉴 테이블과 레코드는 물리 삭제하지 않는다.
- 기존 판매 데이터는 화면과 지출 집계에서 제외한다.
- 하단 내비게이션은 대시보드, 기록, 내역, 통계, 설정 순서로 제공한다.
- 주요 터치 대상은 최소 44px이며 키보드와 스크린 리더로 사용할 수 있어야 한다.
